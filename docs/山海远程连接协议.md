# 山海远程连接协议

手机端（Flutter App）跨端连接桌面端的通信协议。支持两种连接方式：

- **局域网直连**（默认）：桌面端起一个局域网 WebSocket 服务（`47800`，监听 `0.0.0.0`），手机连同一 WiFi 后通过「配对码」鉴权。
- **网关中继**（外网可达）：桌面端作为 Host、手机端作为 Client 都连网关 bridge（`wss://aisocket.bjctykj.com/ws`），用同一会员账号登录后按 memberID 自动配对，任何网络都能连（见「8. 网关中继连接」）。

> 所有消息均为 JSON 文本帧，一条消息一个 JSON 对象。

## 1. 连接与配对

### 1.1 开启服务

用户在桌面端「设置 → 远程连接」打开开关。桌面端生成一次性 **6 位数字配对码**（5 分钟有效），并在设置面板显示「本机 IP + 端口 + 配对码」。

### 1.2 配对握手

手机端连上 `ws://<ip>:<port>` 后，先发送配对消息：

```json
{ "type": "pair", "code": "123456" }
```

| 服务端响应 | 含义 |
|-----------|------|
| `{ "type": "paired", "token": "<hex>" }` | 配对成功，此后可发命令、收事件 |
| `{ "type": "error", "message": "配对码错误" }` | 配对码错误 |
| `{ "type": "error", "message": "配对码已过期…" }` | 配对码超时，需在桌面端重新开启 |

未配对就发命令，服务端返回 `{ "type": "error", "message": "未配对，请先发送 pair" }`。

## 2. 客户端 → 服务端：命令

命令统一格式：

```json
{ "type": "cmd", "id": 1, "cmd": "<命令名>", "payload": { } }
```

`id` 为客户端自增序号，用于匹配 `cmd_result`。命令处理结果：

```json
{ "type": "cmd_result", "id": 1, "ok": true, "data": { } }
{ "type": "cmd_result", "id": 1, "ok": false, "error": "错误描述" }
```

### 命令清单

| cmd | payload | data（成功返回） |
|-----|---------|------------------|
| `list_sessions` | — | 会话摘要数组（见 SessionSummary） |
| `get_history` | `{ sessionId }` | 历史消息数组（见 HistoryItem） |
| `get_supervisor_history` | — | 会话管家历史消息数组 |
| `run_supervisor` | `{ message }` | 管家最终回复 string |
| `get_models` | — | 模型数组 |
| `send_message` | `{ sessionId, message, mode? }` | `{ ok, message, result? }` |
| `stop_session` | `{ sessionId }` | `{ ok: true }` |
| `resend` | `{ sessionId, userMessageIndex, newContent? }` | 最终正文 string |
| `resume` | `{ sessionId }` | 最终正文 string |
| `retry` | `{ sessionId }` | 最终正文 string |
| `create_session` | `{ title?, workdir? }` | `{ sessionId }` |
| `rename_session` | `{ sessionId, title }` | `{ ok: true }` |
| `delete_session` | `{ sessionId }` | `{ ok: true }` |
| `set_workdir` | `{ sessionId, workdir }` | `{ ok: true }` |
| `set_model` | `{ sessionId, modelId }` | `{ ok, message }` |
| `switch_session` | `{ sessionId }` | `{ ok: true }` |
| `respond_approval` | `{ requestId, outcome }` | `{ ok: true }` |
| `respond_ask` | `{ requestId, answer }` | `{ ok: true }` |
| `cancel_ask` | `{ requestId }` | `{ ok: true }` |
| `get_token_stats` | — | token 快照 |

> `send_message` 的 `mode` 可选 `insert`（默认，busy 时追加不打断）/ `queue`（busy 时排队）。空闲会话两种等价，均异步执行；真正的正文结果通过事件流（`delta` + `session_activity`）推送，命令本身只返回「已下发」。

## 3. 服务端 → 客户端：事件

事件统一格式：

```json
{ "type": "event", "event": "<事件名>", "payload": { } }
```

### 事件清单

| event | payload |
|-------|---------|
| `delta` | `{ sessionId, text }` 流式正文增量 |
| `reasoning` | `{ sessionId, text }` 流式思考增量 |
| `tool_trace` | `{ trace }` 工具调用/结果（result 已截断到 4000 字符） |
| `session_activity` | `{ sessionId, kind }` kind=`start`/`end` |
| `user_message` | `{ sessionId, message, turnSeq }` 实时用户气泡 |
| `approval_request` | `{ id, sessionId?, toolName, args, riskLevel }` |
| `ask_request` | `{ id, sessionId?, question, options?, multiple?, placeholder?, kind?, sessionOptions?, modelOptions? }` |
| `supervisor_result` | `{ sessionId, title, result?, error? }` |
| `token_stats` | `{ sessionId, stats }` |
| `current_session_changed` | `{ sessionId }` |

## 4. 数据结构

### SessionSummary（list_sessions 返回项）

```jsonc

  "title": "会话标题",
  "workDir": "/path/to/dir",
  "busy": false,           // 是否正在执行
  "active": true,          // 是否当前激活会话

  "modelName": "DeepSeek V3",
  "approvalPolicy": "ask", // ask | workdir | never

  "stepCount": 3,          // 本轮已执行工具步数
```

### HistoryItem（get_history 返回项）

```jsonc
[
  { "kind": "user", "content": "…", "attachments": [], "turnSeq": 1 },
  { "kind": "assistant", "content": "…", "reasoningContent": "…", "turnSeq": 1, "turnDuration": 12345 },
  { "kind": "tool", "trace": { "kind": "tool-result", "sessionId": "…", "callId": "…", "name": "read_file", "args": {}, "result": "…", "durationMs": 123 } }

```

## 5. 典型交互时序

```
手机                                   桌面端
  │   ws://ip:47800 连接                   │
  │ ── pair {code} ──────────────────────▶ │ 校验配对码
  │ ◀── paired {token} ────────────────── │
  │ ── cmd list_sessions ───────────────▶ │
  │ ◀── cmd_result {data:[sessions]} ──── │
  │ ── cmd get_history {sessionId} ─────▶ │
  │ ◀── cmd_result {data:[items]} ─────── │
  │ ── cmd send_message {sid,msg} ──────▶ │ 下发任务（异步执行）
  │ ◀── cmd_result {ok,message} ──────── │
  │ ◀── event user_message ────────────── │ 实时用户气泡
  │ ◀── event session_activity{start} ── │ 任务开始
  │ ◀── event tool_trace ──────────────── │ 工具步骤
  │ ◀── event delta ───────────────────── │ 流式正文
  │ ◀── event session_activity{end} ──── │ 任务结束
  │ ── cmd get_history ─────────────────▶ │ 拉取完整结果
  │ ── cmd respond_approval ────────────▶ │ 审批应答（如有）
```

## 6. 安全边界

- **局域网直连**：服务监听 `0.0.0.0`，但配对码一次性 + 5 分钟过期，且数据不出本机所在局域网（无云端中继）。
- **网关中继**：数据经网关 bridge 中转（TLS 加密），鉴权用会员 JWT；同账号（memberID）自动配对，不暴露公网端口、无需配对码。
- **结果截断**：工具结果转发前截断到 4000 字符，完整内容仍在桌面端磁盘持久化，手机端按需不传输超大 payload。
- **无凭证泄露**：协议不传输账号密码 / API Key；`get_models` 返回的模型项已由桌面端脱敏处理（与桌面端下拉框同源）。

## 7. 手机端两种模式

手机端 App 提供两种使用模式，对应桌面端的两个窗口：

| 模式 | 对应桌面端 | 发消息命令 | 语义 |
|------|-----------|-----------|------|
| **会话模式** | 聊天窗口 | `send_message { sessionId, message }` | 直接对某个会话负责：列出会话 → 进入会话 → 发消息执行、看工具步骤、应答审批/提问 |
| **管家模式** | 会话管家窗口 | `run_supervisor { message }` | 直接对会话管家负责：和管家对话，由管家调度/配置所有会话（管家会弹会话/模型选择器让用户选） |

- **会话模式**：手机端顶部 `会话` 页 → 会话列表 → 点进具体会话聊天，`send_message` 等同「手动切到该会话发消息」，结果通过 `delta` + `session_activity` 事件流实时回传。
- **管家模式**：手机端顶部 `管家` 页 → 与管家对话，`run_supervisor` 走管家工具集；管家需要用户选择时（`choose_session`/`choose_model`/`ask_user`）会推送 `ask_request` 事件（`kind=session-picker`/`model-picker`/`text`），手机端弹选择器/提问卡片，用户选完用 `respond_ask`/`cancel_ask` 应答。
- 两种模式共用同一套事件流（`delta`/`tool_trace`/`approval_request`/`ask_request`/…），仅发消息命令不同。

## 8. 网关中继连接（外网可达）

局域网直连要求手机与电脑在同一 WiFi。要任何网络都能连，走网关 bridge 中继：

### 8.1 拓扑

```
桌面端（Host）  ──wss──▶ 网关 bridge（aisocket.bjctykj.com/ws）
手机端（Client）──wss──▶ 网关 bridge（aisocket.bjctykj.com/ws）
                            └─ 按 memberID 自动配对，双向透明转发
```

### 8.2 鉴权与配对

- 桌面端登录后拿会员 JWT，作为 **Host** 连 `wss://aisocket.bjctykj.com/ws?role=host&token=<JWT>`。
- 手机端用**同一会员账号**登录（`POST https://agent.bjctykj.com/api/member/login`，密码 SHA-256 小写 hex），拿到 JWT 后作为 **Client** 连 `wss://aisocket.bjctykj.com/ws?role=client&token=<JWT>`。
- 网关解析 JWT 得 memberID，把 Client 自动配对到同 memberID 的 Host，之后两端消息透明互转，**无需配对码**。

### 8.3 消息协议不变

网关只做透明转发，不解析业务消息。桌面端 Host 与手机端 Client 之间仍走本文档第 2/3 节的命令/事件 JSON 协议（`cmd` / `cmd_result` / `event`），完全复用局域网直连的协议。

网关自身会下发控制消息（类型也是 `type` 字段，手机端需识别并忽略或处理）：

| type | 含义 |
|------|------|
| `connected` | 已连上中继（Host 可能仍离线） |
| `host_connected` | Host 上线 |
| `host_disconnected` | Host 离线（手机端应提示「桌面端离线」） |
| `client_connected` / `client_disconnected` | Client 增减（Host 侧用于展示连接数） |
| `error` | 中继错误（如 message_too_large） |

### 8.4 部署前置

网关 bridge 监听 `9202` 端口，需在网关 nginx 为 `/ws` 增加 WebSocket 升级转发（`proxy_set_header Upgrade $http_upgrade` / `Connection "upgrade"` + `proxy_read_timeout 600s`），或联调期直连 `9202`。此步属网关生产环境运维，需网关部署权限。
