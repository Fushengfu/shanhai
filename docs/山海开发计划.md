# 山海开发计划

> 版本：v2.0（重新设计）
> 日期：2026-08-17
> 依据：《山海系统结构设计》（架构）+《山海接口契约与数据模型》（接口）+《智能体设计文档》（方法论）
> 原则：依赖驱动分阶段、任务拆到文件级、每任务有完成定义（DoD）、每里程碑有可量化验收、宁可停不可过

---

## 一、开发目标与范围

### 1.1 目标

从零实现一个参考 DSH 架构的桌面智能体，交付三层：

1. **内核底座**（`@shanhai/kernel` + `@shanhai/kernel-modules`）：自研插件内核，接口对齐 DSH（`ctx`/`inject`/`effect`/`slots`/`fiber` 同名同义）。
2. **能力插件**（11 个 `@shanhai/<feature>` 包）：agent 循环、会话、审批、压缩、工具、LLM、记忆、语音、computer-use、模型网关、认证，全部遵循能力缝（Definition/Provider/Consumer）。
3. **产品壳**（`apps/runtime` + `apps/desktop`）：Electron 桌面端，主进程 boot host，IPC 传输，React 渲染。

最终跑通完整闭环：**登录 → 派活 → 编排 → 工具执行 → 结果**。

### 1.2 范围（做 / 不做）

| 范围 | 内容 |
|------|------|
| ✅ 做 | 自研内核 K1~K5；11 个能力插件；Electron 产品壳；账号密码登录（SHA-256）+ 模型网关；Triage 多专家编排 + 断点续跑 + 会话隔离；自修改（聊天式自我升级） |
| ❌ 不做（本期外） | 直接用真 DSH 内核（仅接口对齐预留、换核零迁移）；插件市场运营与第三方生态；Windows/Linux 打包（先 macOS）；自定义 API Key 登录方式（登录只有账号密码一种） |

## 二、技术选型

| 项 | 选择 | 理由 |
|----|------|------|
| 语言 | TypeScript（strict，全项目） | 全栈类型安全，接口契约即类型 |
| 包管理 | pnpm workspace（`apps/*` + `packages/*`） | monorepo 标准，跨包本地链接 |
| 运行时 | Node ≥ 20（主进程 + 运行时） | `node:vm` 沙箱、子进程、fs 原生支持 |
| 测试 | vitest（包级 `tests/`，`.spec.ts`） | TS 原生、快、契合 monorepo |
| 库构建 | tsup（库包 → ESM + CJS + d.ts） | 零配置多格式产物 |
| 桌面 | Electron + Vite + React（renderer） | 主/预加载/渲染三进程；Vite HMR |
| 进程通信 | IPC（`ipcMain.handle`/`ipcRenderer.invoke` + `contextBridge` 白名单） | 对齐 DSH 传输抽象，不起 HTTP |
| 签名 | Ed25519（`@noble/ed25519` 或 Node crypto） | 插件清单完整性 |
| 密码 | SHA-256（小写 hex） | 登录规范（明文会被网关拒） |
| 沙箱 | `node:vm`（K5 host 半）+ 工具子进程 | vm 非安全边界，等同 bash 信任立场 |

## 三、包依赖拓扑（决定开发顺序）

13 个包按依赖分层；**同层内互不依赖可并行，跨层严格串行**。

```
Layer 0（无依赖）
  kernel          —— K1 组合运行时 + K2 版本生命周期 + K4 安全 + K5 自修改
        │
Layer 1
  kernel-modules  —— K3 模块系统（依赖 kernel 类型）
        │
Layer 2（依赖 kernel，互不依赖，可并行）
  llm          —— Model 接口 + DeepSeek provider
  tools        —— ToolContract + 原子工具（read/write/run_command）
  session      —— Session 类型化事件日志
  memory       —— MemoryStore 分层记忆
  auth         —— AuthService + CredentialStore
  voice        —— VoiceService（STT/TTS）
  computer-use —— ComputerUseService（screenshot/click/type/key）
        │
Layer 3（依赖 Layer 2）
  approval      —— ApprovalService（依赖 session + tools）
  compaction    —— Compactor（依赖 session）
  llm-gateway   —— LlmGateway（依赖 llm + auth）
        │
Layer 4（依赖 Layer 2 + 3）
  agent         —— AgentLoop（依赖 llm + tools + session + approval + compaction）
        │
Layer 5（依赖全部）
  runtime       —— host 装配（Kernel + 全部能力插件）
        │
Layer 6
  desktop       —— Electron 壳（依赖 runtime）
```

**依赖说明**（关键，避免返工）：
- `approval.requiresApproval(tool)` 需要 `ToolContract`，`approval.request(session, ...)` 需要 `Session` → approval 排在 tools/session 之后。
- `agent` 是组合点，几乎依赖所有能力 → 排最后，且必须在 Layer 2/3 全部稳定后开发，否则接口反复改。
- `llm-gateway` 登录后拿 `apiKey`/`baseUrl`，故依赖 `auth` 的凭证与 `llm` 的 `Model` 接口。

## 四、阶段划分与任务拆解（WBS）

按依赖层分 7 个批次。每个任务标注：**交付物 + 完成定义（DoD）**。DoD = typecheck 通过 + 对应测试通过 + 接口对齐契约文档。

### 批次 7：完整闭环（端到端）

| 任务 | 内容 | 验收（可量化） |
|------|------|----------------|
| T7.1 登录链路 | 账号密码（SHA-256）→ JWT → 拉模型 → 凭证落盘（600 权限） | 登录成功拿到模型列表；重启免登录；密码不落盘 |
| T7.2 派活链路 | 用户输入 → Triage 拆解 → 路由专家 → 执行 → 汇总 | 一个真实任务（如"整理本月报销"）跑通，含工具调用 |
| T7.3 安全链路 | 危险命令审批 + 写文件快照回滚 | 危险操作被拦截需人工确认；回滚可恢复原文件 |
| T7.4 会话链路 | 多会话隔离 + 事件日志持久化 + 断点续跑 | 中断后「继续执行」从断点恢复 |
| T7.5 自修改链路 | 聊天说"把发送按钮改绿色"→ plugin_define/run → UI 热更新 | UI 实时更新不重启；stop 撤回恢复 |

**里程碑 M7（最终验收）**：登录→派活→编排→工具执行→结果 全链路跑通，5 条链路均有手工 + 自动化验证记录。

## 六、风险与回退

| 风险 | 概率/影响 | 缓解 | 回退 |
|------|-----------|------|------|
| DSH 接口理解偏差（fiber/epoch 语义） | 中/高 | 开发前再读 `vendor/cordis` 源码逐项对照；M1 逐项核对契约 | 内核接口偏离即返工 M1，不向下蔓延 |
| agent 组合点接口反复改 | 中/中 | agent 排 Layer 4，依赖全部稳定后开发 | 冻结 Layer 2/3 接口后再写 agent |
| vm 沙箱逃逸 | 低/高 | vm 非安全边界、等同 bash 信任立场；危险操作走审批 | 敏感操作降级到工具子进程 |
| 网关对接不稳（agent.bjctykj.com） | 中/中 | mock 回退；llm-gateway 降级策略 | 用 DeepSeek 官方 provider 兜底 |
| Electron IPC 复杂度 | 中/中 | 对齐 DSH 传输抽象，RPC 信封统一 | 单进程先跑通再拆 IPC |
| 多专家编排失控（成本/死循环） | 中/高 | maxSteps + 预算上限 + 重复检测；先单 Agent 再多 Agent | 降级为单 Agent 编排 |

**总原则**：每个里程碑独立可回退；宁可停（单 Agent 跑通）不可过（过早拆多 Agent）。

## 七、开发约定

1. **测试先行**：每块配包级测试，测试描述行为（`should xxx`），不描述正确性空话。
2. **一切皆插件**：新能力 = 新插件，声明 `inject`，内核负责时序，不手排顺序。
3. **可逆副作用**：所有注册返回 Disposer，fiber 撤销逆序撤销——这是热插拔的硬前提。
4. **能力缝三角色**：一个能力一个包，Definition/Provider/Consumer 齐全，永不只有一角。
5. **安全优先**：危险操作审批、能力清单强制、文件写前快照，宁可停不可过。
6. **简单优先**：先单 Agent 跑通再考虑多 Agent；先可用的降级方案，完整 LSP/多平台等作为后续演进。
7. **每任务先对齐契约文档**：改动接口先改《山海接口契约与数据模型》，再写实现，禁止实现与契约漂移。
