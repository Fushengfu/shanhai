## 一、内核接口契约（K1~K5）

### 1.1 Fiber（组合运行时，对齐 Cordis）

```ts
/** fiber 六态（对齐 Cordis FiberState） */
type FiberState = 'PENDING' | 'LOADING' | 'ACTIVE' | 'FAILED' | 'UNLOADING' | 'DISPOSED'

/** 副作用撤销函数：立即执行或返回 Promise */
type Disposable = () => void | Promise<void>

/** effect 返回体：单个 disposer、Promise、或（异步）Iterable */
type Effect = Disposable | Promise<Disposable> | Iterable<Disposable> | AsyncIterable<Disposable>

interface Fiber {
  /** 唯一 id（root=0；disposed 后为 null） */
  readonly uid: number | null
  /** 当前生命周期状态 */
  readonly state: FiberState
  /** 插件配置（经 Config schema 校验后） */
  readonly config: unknown
  /** 已注入服务的实现快照（未加载时 undefined） */
  readonly store: Record<string, unknown> | undefined
  /** 注册副作用：execute 立即执行，disposer 逆序撤销 */
  effect(execute: () => Effect, label?: string): Disposable
  /** 等待 settle（加载/卸载完成），启动错误会 reject */
  await(): Promise<Fiber>
  /** 卸载插件并等待 cleanup 完成 */
  dispose(): Promise<void>
  /** 卸载后立即用当前配置重载 */
  restart(): Promise<void>
}
```

### 1.2 Context（Proxy，对齐 Cordis）

```ts
/** Context 是 Proxy：`ctx.xxx` 直接读服务，硬依赖用 inject 声明 */
interface Context {
  /** 所属 fiber */
  readonly fiber: Fiber
  /** 根上下文（每个子上下文共享） */
  readonly root: Context

  // 作用域（extend 不修改父上下文）
  extend(meta?: object): Context
  /** 服务作用域隔离：同名服务在不同 label 下解析到不同实现 */
  isolate(name: string, label?: symbol): Context
  /** 服务配置拦截：子上下文下插件启动时合并该服务的 config */
  intercept(name: string, config: unknown): Context

  // 插件（来自 RegistryService）
  plugin(plugin: Plugin, config?: unknown): Fiber & PromiseLike<Fiber>
  inject(deps: Inject, callback: Plugin.Function): Fiber & PromiseLike<Fiber>

  // 事件（来自 EventsService）
  on(name: string, listener: (...args: any[]) => any, options?: boolean | EventOptions): () => boolean
  once(name: string, listener: (...args: any[]) => any, options?: EventOptions): () => boolean
  emit(name: string, ...args: any[]): void
  parallel(name: string, ...args: any[]): Promise<void>
  serial(name: string, ...args: any[]): Promise<unknown>
  bail(name: string, ...args: any[]): unknown
  waterfall(name: string, ...args: any[]): unknown
}
```

### 1.3 Service（符号化扩展点，对齐 Cordis）

```ts
abstract class Service<T = never> {
  /** 服务名（构造时自动 `ctx.reflect.provide(name, this, check)`） */
  readonly name: string

  // 静态符号（扩展点）
  static readonly invoke: symbol    // 可调用服务（ctx.logger() 直接调用）
  static readonly check: symbol     // 可用性谓词：返回 false 则服务不可用
  static readonly extend: symbol    // 派生扩展服务实例
  static readonly config: symbol    // 拦截配置的 phantom 类型参数
  static readonly resolveConfig: symbol // 合并拦截配置（Config.merge 或 Object.assign）

  constructor(ctx: Context, name: string)
}
```

### 1.4 Plugin（三种形态，对齐 Cordis）

```ts
/** 依赖声明：数组（只要服务）或 map（服务 + 该服务的拦截配置） */
type Inject<M> = (keyof M)[] | { [K in keyof M]?: M[K] }

interface PluginBase<T = unknown> {
  name?: string                       // 诊断名（fiber 名 / logger 名）
  Config?: StandardSchemaV1<T>        // 配置校验 schema（启动前验证）
  inject?: Inject                     // 硬依赖：齐了才加载
  provide?: string | string[]         // 声明提供的服务名
  intercept?: Record<string, boolean> // 声明消费哪些服务的拦截配置
}

type Plugin<T = unknown> =
  | Plugin.Function<T>    // (ctx, config) => any
  | Plugin.Constructor<T> // class，new (ctx, config)
  | Plugin.Object<T>      // { apply(ctx, config) }
```

### 1.5 事件五种 dispatch（对齐 Cordis）

| 模式 | 语义 | 返回 |
|------|------|------|
| `emit` | 同步执行，忽略返回值 | void |
| `parallel` | 并发 await 所有监听器 | Promise<void> |
| `serial` | 顺序 await，直到某个返回 bail 值 | 首个 bail 值 |
| `bail` | 同步执行，直到某个返回 bail 值 | 首个 bail 值 |
| `waterfall` | 组合监听器，末参是 `next()`，不调用即短路 | 最外层返回值 |

**内置事件（internal/*）**：`internal/plugin`（fiber 创建/清除）、`internal/status`（状态变化）、`internal/config`（waterfall 解析配置）、`internal/get`/`internal/set`（waterfall 读写服务）、`internal/update`（waterfall 配置更新）、`internal/listener`（bail 拦截监听注册）。

### 1.9 自修改（K5，对齐 DSH extensions）

```ts
/** 动态 package（仅内存态：不落盘、不存活重启、会话级隔离） */
interface DynamicPackage {
  id: string                    // dyn-<n>
  name: string
  purpose: string
  code?: string                 // host 半源码（node:vm 评估，非安全边界）
  client?: string               // browser 半源码（投递到渲染进程）
  status: 'defined' | 'running' | 'stopped'

}

/** 自修改工具集（model-facing，五工具） */
interface SelfModifyTools {
  inspect(what?: 'services' | 'plugins' | 'tools' | 'packages' | 'slots', name?: string): unknown
  define(def: { name: string; purpose: string; code?: string; client?: string }): DynamicPackage
  run(id: string): Promise<{ clientDelivered: boolean }>
  stop(id: string): Promise<void>
  undefine(id: string): Promise<void>
}
```

**沙箱约束**：动态 package 的 ctx façade 不暴露 `effect()`，cleanup 只限 `on`/`provide`/`tools.register` 三条自动撤销路径——从机制上保证可热插拔。

### 3.4 用户与凭证（登录）

```ts
/** 登录会话（JWT） */
interface AuthSession {
  token: string
  username: string
}

/** 网关下发的模型项（登录后拉取） */
interface GatewayModel {
  id: string; name: string; tier: ModelTier
  apiKey: string; baseUrl: string
}

/** 本地凭证（~/.shanhai/config.json，权限 600；密码绝不落盘） */
interface LocalCredential {
  username: string
  token: string                        // JWT（可刷新）
  customModels?: GatewayModel[]        // 用户自定义模型（可选来源）
}

/** 凭证存取（只存 token + username，密码只在登录请求瞬间使用） */
interface CredentialStore {
  load(): Promise<LocalCredential | null>
  save(cred: LocalCredential): Promise<void>
  clear(): Promise<void>
}

/** 认证服务（账号密码登录 → JWT → 拉模型） */
interface AuthService {
  login(username: string, passwordSha256Hex: string): Promise<AuthSession>
  logout(): Promise<void>
  fetchModels(token: string): Promise<GatewayModel[]>
}
```

**登录规则（硬约束）**：
- 登录方式只有「账号密码登录」一种，不提供「自定义 API Key」作为登录方式。
- 密码必须 **SHA-256 加密后以小写 hex 提交**（`password: sha256Hex(明文)`），服务端按密文校验。
- 模型来源两种（登录后可切换）：① 网关下发模型（默认，`apiKey` + `baseUrl` 由网关提供）；② 用户自定义模型（可选，OpenAI 兼容端点 + Key）。
- 凭证只保存在本地 `~/.shanhai/config.json`（权限 600），密码绝不落盘。

## 四、关键流程设计

### 4.1 agent 循环（ReAct）详细流程

```
run(message, { maxSteps, systemPrompt })
  ├─ 1. 组装 messages：[system] + 历史(user/assistant) + [user: message]
  ├─ 2. 循环 step < maxSteps：
  │    ├─ 2.1 decide(messages)：模型决策（优先流式 stream，否则 complete）
  │    │      - 有 toolCall → 进入 2.2
  │    │      - 无 toolCall → 落 assistant/message + turn/end，返回 text
  │    └─ 2.2 handleToolCall(call)：
  │         ├─ 落 tool/call 事件
  │         ├─ 审批门：requiresApproval(tool) → request → outcome !== 'allowed-once' 则终止
  │         ├─ 执行：tool.execute(call.args)（带超时 + 容错）
  │         ├─ 落 tool/result 事件
  │         ├─ 结果回喂：messages.push(assistant.toolCall + tool 消息)
  │         └─ 重复调用提醒：连续 N 次同工具 → 注入提醒
  └─ 3. 超 maxSteps → 抛错"未收敛"
```

### 4.2 审批时序

```
AgentLoop.handleToolCall
  → ApprovalService.requiresApproval(tool) ? false : 直接执行
  → ApprovalService.request(session, { id, toolName, args, riskLevel })
      ├─ 落 approval/request 事件
      ├─ policy === 'never' → outcome = 'rejected'
      ├─ approver 存在 → await approver(req)（UI 弹窗异步应答）
      ├─ approver 缺失 → 'unavailable'（失败关闭）
      └─ 落 approval/outcome 事件
  → outcome === 'allowed-once' → 执行；否则落 tool/result(error) + 终止本轮
```

### 4.3 模型路由与降级

```
resolveModel(tier, override?)
  ├─ 候选列表：override > 自定义模型 > 同层网关模型 > 其他层 > 任意模型
  └─ invoke() 遍历候选：
       - 模型不可用（403/402/余额不足）→ 降级换下一个
       - 参数/网络错误 → 直接抛出（不掩盖真实问题）
```

### 4.4 自修改（K5）五个工具

| 工具 | 输入 | 输出 |
|------|------|------|
| `plugin_inspect` | `{ what?, name? }` | 服务/插件/工具/动态 package/slot 表面报告 |
| `plugin_define` | `{ name, purpose, code?, client? }` | `dyn-<n>` id + 卡片 |
| `plugin_run` | `{ id }` | host 半评估 + browser 半投递（带 UI 需 approve） |
| `plugin_stop` | `{ id }` | 撤回 host/browser 半，定义保留 |
| `plugin_undefine` | `{ id }` | 停止并遗忘定义 |

### 4.5 登录与模型下发流程

```
登录(username, password)
  ├─ 1. sha256Hex(password) → 小写 hex 密文
  ├─ 2. POST /api/member/login { username, password: 密文 }
  │      ├─ 成功 → 返回 JWT token
  │      └─ 失败 → 返回错误（明文密码会得到 invalid password）
  ├─ 3. GET /api/member/models（Authorization: Bearer <token>）
  │      └─ 返回含 apiKey + baseUrl 的模型项列表
  ├─ 4. CredentialStore.save({ username, token })（不存密码）
  ├─ 5. 模型来源：网关下发（默认）/ 用户自定义（可选，可切换）
  └─ 6. LlmGateway 按 tier 路由到对应模型（flagship/value/vision）
```

**关键点**：
- 密码只在步骤 2 的请求瞬间使用，之后立即丢弃，绝不落盘。
- token 持久化到 `~/.shanhai/config.json`（权限 600），重启后免登录。
- token 失效 → 重新走登录流程（不提供 API Key 登录）。

### 4.6 网关接口实测（2026-08-17 真实联调）

> 以下为用真实凭证联调确认的网关接口契约，与 4.5 的会员接口分离。

**两个网关分工**：

| 网关 | 域名 | 职责 | 鉴权 |
|------|------|------|------|
| 会员网关 | `https://agent.bjctykj.com` | `POST /api/member/login`、`GET /api/member/models` | JWT（memberToken） |
| 模型网关 | `https://aigateway.bjctykj.com` | `POST /api/v1/chat/completions` | apiKey（`sk-...`） |

**模型调用（OpenAI 兼容，但有网关包装）**：

```
POST https://aigateway.bjctykj.com/api/v1/chat/completions
Header: Authorization: Bearer <apiKey>
Body: { model, messages, tools?, stream? }
```

非流式响应（`stream: false`）——外层是 `{ code, data }` 包装：

```json
{
  "code": 0,
  "data": {
    "id": "...", "object": "chat.completion", "model": "deepseek-v4-flash",
    "choices": [{
      "index": 0,
      "message": { "role": "assistant", "content": "最终答案", "reasoning_content": "思维链" },
      "finish_reason": "stop"
    }]
  }
}
```

流式响应（`stream: true`）——标准 SSE `data: {...}`，末尾 `data: [DONE]`：

```
data: {"choices":[{"delta":{"content":null,"reasoning_content":"思考..."}}]}
data: {"choices":[{"delta":{"content":"最终答案","reasoning_content":null},"finish_reason":"stop"}]}
data: [DONE]
```

**关键结论**：

1. **路径是 `/api/v1/chat/completions`**（非 OpenAI 标准 `/v1/chat/completions`，也非裸 `/chat/completions`）。
2. **thinking mode**：推理模型先流式输出 `reasoning_content`（思维链），再输出 `content`（最终答案）；UI 流式渲染只取 `content`。
3. **reasoning_content 回传**：带工具调用的多轮请求，下一轮必须原样回传上一轮的 `reasoning_content`，否则网关报 400（"reasoning_content must be passed back"）。
4. **模型不可用降级**：`code != 0` 或 HTTP 403/402 → 换候选模型；参数/网络错 → 直接抛。
