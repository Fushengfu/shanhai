> 版本：v1.0
> 日期：2026-08-17
> 定位：山海桌面智能体的系统结构设计（参考 DeepSeek Harness 架构重新梳理）
> 参考：`.dsh-src/`（DeepSeek Harness 源码）+ 智能体设计文档（方法论）

## 一、设计原则（源自 DSH 的架构哲学）

DSH（DeepSeek Harness）的核心是 **「一切皆插件」**，由 vendored Cordis（组合运行时）驱动。山海沿用这一哲学，提炼出五条设计原则：

| 原则 | 含义 | DSH 对应 |
|------|------|---------|
| **一切皆插件** | 宿主、工具、UI、语音、记忆、自升级全是插件，经 `ctx.effect()` 贡献、返回 Disposer | Cordis composition |
| **能力缝（capability seam）** | 每个能力拆成「Service Definition / Provider / Consumer」三角色，永不只有一角 | dsh-session / dsh-llm 等 |
| **双端包** | host 半（Service/Event）+ client 半（浏览器 bundle + slots），`/client` 子路径导出 | dsh-client-* |
| **不可变版本 + 可回滚** | 版本一经发布不可变，`currentVersion` 只在完全成功后更新，失败不动、可回滚 | currentPackageId/nextPackageId |
| **自修改** | agent 能检查/挂载/升级自己的插件 | dsh-tool-cordis |

外加一条业界共识（Anthropic/Google/OpenAI 一致强调）：**编排层与工具接口 ≥ 模型本身**——把 Agent 做成「声明式配置」，把工具做成「标准化契约」。

以及一条**硬性原则（热插拔的前提）**：**注册即副作用（Registrations are effects）**——插件的所有贡献（服务 `provide`、事件 `on`、副作用 `effect`、工具 `register`、UI `slots.register`）都必须返回 disposer，fiber 卸载时逆序撤销。**凡是没走这条路径的「裸副作用」（直接改 globalThis、起定时器、开后门进程），都无法热插拔。**

## 二、整体系统架构设计

### 2.1 六层架构 + 内核底座

从用户交互到数据存储逐层解耦，安全护栏贯穿所有层，内核底座横切支撑：

```
┌──────────────────────────────────────────────────────────────┐
│ ① 用户交互层                                                  │
│    悬浮球/窗口 UI · 全局快捷键 · 聊天界面 · 确认弹窗           │
├──────────────────────────────────────────────────────────────┤
│ ② Agent 编排层（大脑）                                        │
│    主控统筹官（Triage 路由 + 任务拆解 + 结果汇总）              │
│    专家 Agent 池（AgentLoop ReAct 循环）                       │
├──────────────────────────────────────────────────────────────┤
│ ③ 模型网关层                                                  │
│    路由（旗舰/性价比/视觉）· 缓存 · 计费 · 降级重试            │
├──────────────────────────────────────────────────────────────┤
│ ④ 工具执行层                                                  │
│    原子工具 · 命令行工具集 · 复合技能（Skill）                 │
│    命令执行器 · 视觉操作（截图/OCR/键鼠）                       │
├──────────────────────────────────────────────────────────────┤
│ ⑤ 安全与沙箱层（横切，所有写操作必经）                          │
│    命令语义审计 · 权限分级 · 审批 · 快照回滚                    │
├──────────────────────────────────────────────────────────────┤
│ ⑥ 记忆与存储层                                                │
│    短期记忆（上下文）· 工作记忆（scratchpad）· 长期记忆（分层） │
└──────────────────────────────────────────────────────────────┘
                          ↑ 支撑所有层
┌──────────────────────────────────────────────────────────────┐
│ 内核底座（K1~K5，横切）                                       │
│    组合运行时 · 版本生命周期 · 模块系统 · 安全 · 自修改         │
└──────────────────────────────────────────────────────────────┘
```

### 2.2 三进程模型

```
主进程（Electron Shell） ←─IPC─→ Agent 运行时 ←─IPC─→ 工具执行子进程
```

| 进程 | 职责 | 崩溃影响 |
|------|------|---------|
| 主进程（Shell） | UI 渲染、全局快捷键、系统托盘 | UI 冻结，内核不受影响 |
| Agent 运行时 | 编排逻辑、状态机、模型调用、Handoff | 任务中断，UI 正常 |
| 工具执行子进程 | 沙箱内执行命令/脚本，用完即销毁 | 仅当前子任务失败 |

### 2.3 数据流（一次典型任务）

```
用户说"帮我整理本月报销"
  → ① 交互层捕获，唤起 Agent
  → ② 主控 Triage 拆解任务，路由到专家（旗舰模型）
  → ③ 模型网关按环节选模型（主控旗舰、专家性价比）
  → ④ 工具执行层：专家扫描/读取/执行
  → ⑤ 写操作前经安全层审计 + 审批 + 备份
  → ⑥ 中间状态写入工作记忆，结果写入长期记忆
  → ① 交互层展示进度，汇总结果回传用户
```

### 2.4 系统分层（内核底座 + 能力插件 + 产品壳）

按「谁依赖谁」再切三层，DSH 当引擎、山海当产品层：

```
┌─────────────────────────────────────────────────────────────┐
│ ③ 产品壳（apps/）                                            │
│    Electron 主进程（boot host，不起 HTTP）+ IPC + React 渲染   │
├─────────────────────────────────────────────────────────────┤
│ ② 能力插件（packages/*，@shanhai/<feature>）                  │
│    agent 循环 · 工具 · 记忆 · 语音 · computer-use · 模型网关   │
│    每个功能一个插件：host 半（Service）+ client 半（Slot/UI）  │
├─────────────────────────────────────────────────────────────┤
│ ① 内核底座（@shanhai/kernel + @shanhai/kernel-modules）       │
│    组合运行时 · 版本生命周期 · 模块系统 · 安全 · 自修改        │
└─────────────────────────────────────────────────────────────┘
```

- **内核底座**：自研插件内核，接口对齐 DSH（`ctx`/`inject`/`effect`/`slots`/`fiber` 同名同义），将来可零迁移换真 DSH 内核。
- **能力插件**：产品能力全部做成插件，声明 `inject` 依赖，内核负责时序。
- **产品壳**：Electron 主进程 boot host，IPC 传输，React 渲染进程。

## 三、内核设计（五块）

### K1 组合运行时（对齐 Cordis 真实机制）

> 本节基于 `vendor/cordis/src/{fiber,context,service,registry,events}.ts` 源码重写，纠正之前「概念层对齐」的错误。

#### 1. Fiber 生命周期（六态 + epoch 驱动，非「依赖齐就 apply」）

```
PENDING ──加载──▶ LOADING ──成功──▶ ACTIVE ──依赖变化──▶ UNLOADING ──▶ PENDING/LOADING
    │                 └──失败──▶ FAILED          └──卸载完成──▶ DISPOSED
```

**核心是 `epoch`，不是布尔依赖检查**：

- 每个依赖实现有唯一 `uid`，fiber 的 `epoch` = 依赖 uid 串（如 `:1:3`）。
- 依赖实现变化 → `epoch` 变化 → 触发 `_reload()`（卸载旧副作用 + 重新执行插件）/ `_unload()`。
- **`effect(execute, label)`**：`execute` 立即执行，返回的 disposer（函数 / Promise / Iterable / AsyncIterable）被收集，fiber 卸载时**逆序**执行。
- **`_reload()` / `_unload()`**：异步加载/卸载流程，支持 async disposer，卸载失败不阻断。

#### 2. Context 是 Proxy（不是 `ctx.get()` 方法）

Cordis 的 `Context` 是一个 **Proxy**，普通属性读取走服务解析器（`ReflectService.handler`）——`ctx.session` 直接读到服务，而不是 `ctx.get('session')`。

- **`extend(meta)`**：创建继承父上下文的子上下文（插件 fiber 的 ctx 就是 `parent.extend({ fiber })`）。
- **`isolate(name, label)`**：服务作用域隔离——同名服务在不同 label 下解析到不同实现，父作用域不受影响。
- **`intercept(name, config)`**：服务配置拦截——子上下文下启动的插件，其依赖服务的 config 被合并。

#### 3. inject 是依赖 map（含拦截配置）

```ts
type Inject<M> = (keyof M)[] | { [K in keyof M]?: M[K] }  // 数组或 map，map 值=拦截配置
```

- 依赖声明支持「数组」（只要服务）和「map」（服务 + 该服务的拦截配置）。
- 依赖变化时 fiber 自动 reload/unload（epoch 驱动），插件不手排顺序。

#### 4. Service 基类（符号化扩展点）

```ts
abstract class Service {
  constructor(ctx, name) { ctx.reflect.provide(name, this, this[Service.check]) }  // 自动注册
  static readonly invoke: symbol   // 可调用服务（如 ctx.logger()）
  static readonly check: symbol    // 可用性谓词
  static readonly extend: symbol   // 派生扩展服务实例
  static readonly resolveConfig: symbol // 合并拦截配置（Config.merge 或 Object.assign）
}
```

#### 5. 事件总线（五种 dispatch 模式）

| 模式 | 语义 |
|------|------|
| `emit` | 同步执行，忽略返回值 |
| `parallel` | 并发 await 所有监听器 |
| `serial` | 顺序 await，直到某个返回 bail 值 |
| `bail` | 同步执行，直到某个返回 bail 值 |
| `waterfall` | 组合监听器，最后一个参数是 `next()`，不调用即短路 |

`ctx.on(name, listener)` 注册监听器，自动随 fiber 卸载；`internal/*` 是框架内置事件（`internal/plugin`、`internal/status`、`internal/config`、`internal/get`、`internal/set`、`internal/update` 等）。

#### 6. 插件注册表（RegistryService）

- **`ctx.plugin(plugin, config)`** → 返回 Fiber（`await fiber` 等待 settle，启动错误会 reject）。
- 插件三种形态：**Function**（`(ctx, config) => ...`）、**Constructor**（class）、**Object**（`{ apply(ctx, config) }`）。
- **`ctx.inject(deps, callback)`** 是 `ctx.plugin({ inject: deps, apply: callback })` 的简写。
- **`@Inject()` 装饰器**：在 class 或方法上声明服务依赖（方法版延迟到依赖可用才调用）。
- 插件可选 `Config`（standard-schema 校验，启动前验证配置）、`provide`（声明提供的服务名）、`name`（诊断名）。

### K2 版本生命周期

**状态机**：`staged → pending → active → failed / inactive`（uninstall 删除全部版本与授权）。

**核心流程（activateVersion）**：

1. **幂等**：已是当前活跃版本则直接返回 fiber。
2. **审批**：`grant !== 'trusted'` 时调 `approve(pkg, fromVersion)`——`reject` 抛错、`trust` 升级 grant。
3. **停旧 fiber**：`disposeRun(rec)` 撤销旧副作用。
4. **启新 fiber**：`kernel.mount({ id, inject, capabilities, apply })`，声明式 inject，依赖缺失挂起 pending。
5. **settle 落版本指针**：fiber settle 到 `active` → `currentVersion = version`；`failed` → `failures++`，达 `maxFailures` 自动停用（inactive）。

**关键性质**：

- `currentVersion` 只在 fiber 完全 settle 到 `active` 后更新；失败不动、可回滚。
- **rollback 跳过审批**：旧版本此前已获授权。
- **看门狗**：连续失败自动停用，避免反复重试坏版本。

### K3 模块系统（双端）

**双端包**：一个插件两个 face，各自独立编译：

- **host 半**：Service/Event（进程内，node）。
- **client 半**：`/client` 导出浏览器 bundle（**零 node import**）。

**`__DSH_BOOT__` 引导**：

- 宿主扫出所有声明 `dsh.client` 的插件，组合 `BootManifest`（`modules` + `plugins`）。
- 渲染进程按清单懒加载 bundle，`parseBootManifest` 在 wire 边界校验（失败响亮报错）。

**客户端懒加载 CJS**：

- `register` 只注册工厂不物化；`require` 递归物化（循环依赖返回部分导出，不无限递归）；`invalidate` 失效重载。

**slots 组合**：

- client 半 `ctx.slots.register({ name, children }, Component)` 挂真实 React 组件。
- `renderSlot(name)` 消费，组件 props 由框架派生（session/store/inject），业务代码不手写订阅。

### K4 安全

**能力清单（least privilege）**：

- 插件声明 `capabilities: { provide?: string[], consume?: string[] }`。
- `guardContext(ctx, caps)` 代理 Context，在 `provide`/`get` 处拦截越界。
- 越界 → 抛错 → `apply` 失败 → fiber `failed`（响亮失败，不静默跳过）。

**Ed25519 签名**：

- 插件清单 `stableStringify`（键序稳定）→ `signPayload`（私钥签名）。
- 加载前 `verifyPayload`（公钥验签），篡改拒绝。

**审批**：`reject / allow / trust`，trust 后更新不再审批（K2 流程里消费）。

**文件快照回滚**：写操作前 `SnapshotStore.snapshot(path)` 备份，`rollback` 回滚、`discard` 确认后丢弃——支撑「信任四可」的可回退。

### K5 自修改（对齐 DSH extensions：agent 修改自己的运行时）

**核心：五个 model-facing 工具，让 agent 在会话中检查、定义、运行、停止自己的插件（含 UI 插件）**——这正是「用户通过聊天自我升级 UI」的支撑。

| 工具 | 作用 |
|------|------|
| `cordis_inspect` | 只读报告：服务、插件 fiber、工具、动态 package、API/events/client slot 表面 |
| `cordis_define` | 记录 package（name + purpose + host 半 code + browser 半 client），语法检查不运行，用户看到卡片 |
| `cordis_run` | vm 沙箱评估 host 半 + 投递 browser 半到页面（带 UI 的需人 approve） |
| `cordis_stop` | 撤回 host 半 + browser 半，定义保留可再跑 |
| `cordis_undefine` | 停止并遗忘定义 |

**关键机制**：

1. **host 半 + browser 半分离**：动态 package 有 host 半（Service/工具，进程内）+ browser 半（UI 组件，浏览器），各自独立编译、独立投递。
2. **vm 沙箱**：host 半在 `node:vm` 评估，隔离 globals（**非安全边界**，信任立场等同 bash 访问）。**沙箱 ctx façade 不暴露 `effect()`**，动态 package 的 cleanup 路径只限于 `on`/`provide`/`tools.register` 三条（都自动撤销），从机制上杜绝「裸副作用」导致无法热插拔。
3. **round-trip 审批**：带 browser 半的 `run` 阻塞在 `cordis/request-run` 事件，需人在页面按 approve 才投递。
4. **slots 热替换**：browser 半通过 `slots.register(Component)` 注册 UI 组件，React 渲染——改 UI = 改 browser 半组件代码，无需重启。
5. **内存态**：动态 package 只活在进程内存，不写文件、不装包、不存活重启；要持久化走正式 Plugin 开发流程。
6. **session 隔离**：一个 session 定义的 package 其他 session 不可见；stop/undefine 后消失。

**「用户聊天自我升级 UI」的完整链路**：

```
用户说"把发送按钮改成绿色"
 → agent cordis_inspect 查看 UI slot 表面（有哪些座位、谁占用）
 → agent cordis_define 定义新 browser 半（绿色按钮组件 + host 半可选）
 → 用户看到 define 卡片 → cordis_run
 → 页面 approve（round-trip 审批）
 → browser 半在页面加载 → React 渲染新按钮（slots 热替换）
 → UI 实时更新，不重启；cordis_stop 撤回恢复原 UI
```

## 四、能力插件设计

**对齐 DSH 的能力缝：一个能力 = 一个包，拆成 Definition / Provider / Consumer 三角色**（而非塞进一个大 SDK）：

| 能力 | 包 | Service Definition（接口） | Provider（实现） | DSH 对应 |
|------|-----|--------------------------|-----------------|---------|
| agent 循环 | `@shanhai/agent` | `AgentLoop`（ReAct：消息→决策→审批→执行→回喂） | 模型 + 工具注册表注入 | dsh-agent-loop |
| 会话 | `@shanhai/session` | `Session`（类型化事件日志，回放即状态） | 内存 + JSONL/SQLite | dsh-session |
| 审批 | `@shanhai/approval` | `ApprovalService`（ask/never + requiresApproval） | UI 异步应答 | dsh-user-approval |
| 压缩 | `@shanhai/compaction` | `Compactor`（token 预算滑动窗口） | — | dsh-compaction |
| 工具 | `@shanhai/tools` | `ToolContract`（name/description/inputSchema/riskLevel/execute） | 原子工具实现 | dsh-tools |
| LLM | `@shanhai/llm` | `Model`（complete/stream） | DeepSeek provider + mock 回退 | dsh-llm |
| 记忆 | `@shanhai/memory` | `MemoryStore`（分层：短期 + 长期配置型/经验型） | 内存 + SQLite | dsh-memory |
| 语音 | `@shanhai/voice` | `VoiceService`（transcribe/synthesize） | mock + 网关 ASR/TTS | — |
| computer-use | `@shanhai/computer-use` | `ComputerUseService`（screenshot/clickAt/typeText/pressKey） | Electron 后端 | — |
| 模型网关 | `@shanhai/llm-gateway` | `LlmGateway`（resolveModel/invoke，路由降级） | 网关 provider + 降级重试 | dsh-llm |
| 认证 | `@shanhai/auth` | `AuthService`（login/logout/fetchModels）+ `CredentialStore` | 网关登录 + 本地凭证（600 权限） | dsh-credentials |

**关键差异（相对旧设计）**：会话、审批、压缩、工具、LLM 从「塞进 agent-sdk 一个包」拆成**独立包**——每个能力一个包，能力缝三角色齐全，这是 DSH 明确要求的（「一个能力缝完整，永不只有一角」）。

**工具契约（Tool Contract）**——安全属性内嵌：

```ts
interface ToolContract {
  name: string;              // 唯一工具名
  description: string;       // 何时用/参数含义/返回什么（隐式 prompt）
  inputSchema: object;       // JSON Schema
  riskLevel: 'readonly' | 'reversible' | 'irreversible' | 'high';
  approvalRequired?: boolean;
  timeoutMs?: number;
  execute: (args) => unknown | Promise<unknown>;
}
```

**角色定义（Role Definition）**——专家即配置：

```ts
interface RoleDefinition {
  id: string; name: string; description: string;
  systemPrompt: string;      // 角色人设与职责边界
  toolSet: string[];         // 注入的原子工具
  skillSet: string[];        // 注入的复合技能
}
```

**agent 循环（对齐 DSH dsh-agent-loop）**：

```
消息 → 模型决策 → 工具审批 → 工具执行 → 结果回喂 → 再决策，直到文本收敛
```

每个可观测步骤落一条类型化会话事件（`turn/*`, `user/message`, `assistant/delta`, `tool/call`, `tool/result`, `approval/*`），**回放日志即状态**。

## 五、产品壳设计

### 进程模型（三进程）

| 进程 | 职责 | 崩溃影响 |
|------|------|---------|
| 主进程（Shell） | UI 渲染、全局快捷键、系统托盘 | UI 冻结，内核不受影响 |
| Agent 运行时 | 编排逻辑、模型调用、Handoff | 任务中断，UI 正常 |
| 工具执行子进程 | 沙箱内执行命令，用完即销毁 | 仅当前子任务失败 |

### IPC 传输（对齐 DSH 传输抽象）

DSH 的 `toFetchHandler(api)` → `{ fetch }` 纯函数 + `InProcessApiClient` 的 `doFetch` 可覆写，使「原生 IPC 化」改动面极小：

- unary RPC 走 `ipcRenderer.invoke` / `ipcMain.handle`
- SSE 事件流走 `webContents.send` / `ipcRenderer.on`
- preload `contextBridge` 只暴露白名单通道，`contextIsolation: true`

## 六、框架骨架目录结构设计

### 6.1 完整目录树


### 6.2 目录 ↔ 架构层对应关系

| 架构层 | 对应目录 |
|--------|---------|
| ① 用户交互层 | `apps/desktop/src/renderer/` |
| ② Agent 编排层 | `packages/agent/`（AgentLoop）+ `packages/session/` + `packages/approval/` + `packages/compaction/` + `apps/runtime/`（装配） |
| ③ 模型网关层 | `packages/llm-gateway/` + `packages/llm/` + `packages/auth/` |
| ④ 工具执行层 | `packages/tools/` + `packages/computer-use/` + `packages/browser-use/` |
| ⑤ 安全沙箱层 | `packages/kernel/src/security/`（横切） |
| ⑥ 记忆存储层 | `packages/memory/` |
| 内核底座 | `packages/kernel/` + `packages/kernel-modules/` |

### 6.3 分层设计约定

1. **一个概念一个文件**：文件名 = 概念名（`fiber.ts`/`service.ts`/`event.ts`），不写 `xxx-impl.ts`、`xxx-utils.ts`。
2. **`types.ts` 只放类型**：不放任何运行时代码。
3. **Service 类默认导出**：函数式插件命名导出 `name/inject/apply`，不混用。
4. **测试放包级 `tests/`**：不放 `src/__tests__`，同名 `.spec.ts`。
5. **双端包用 `/client` 子路径**：浏览器半零 node import。
6. **服务读取走 Context Proxy**（对齐 Cordis）：`ctx.session` 直接读服务，硬依赖用 `inject` 声明；作用域用 `isolate(name, label)`，配置拦截用 `intercept(name, config)`。

## 七、关键设计决策

| 决策 | 结论 | 理由 |
|------|------|------|
| 底座 | 自研内核，接口对齐 DSH | 不直接依赖 DSH rc 版本演进，插件层零迁移 |
| 内核拆包 | 两包（kernel + kernel-modules） | 运行时强耦合放一包，模块系统跨进程独立 |
| 组合语义 | 声明式 inject + epoch 驱动 | 依赖实现变化自动 reload/unload，插件不手排顺序（对齐 Cordis） |
| 能力拆包 | 一个能力一个包（Definition/Provider/Consumer） | 会话/审批/压缩/工具/LLM 独立成包，能力缝三角色齐全 |
| 工具标准 | 统一 Tool Contract，安全属性内嵌 | 安全层一处拦截，处处生效 |
| 编排 | AgentLoop ReAct + 能力缝 | 对齐 DSH，简单优先 |
| 会话 | 类型化事件日志，回放即状态 | 对齐 DSH dsh-session |
| 审批 | ask/never + 落日志 | 对齐 DSH dsh-user-approval |
| 进程 | 三进程隔离 | 故障隔离，工具崩溃不波及核心 |
| 传输 | 原生 IPC（不起 HTTP） | 对齐 DSH 传输抽象，安全 |

## 附：与 DSH 的对照

| DSH | 山海 | 说明 |
|-----|------|------|
| vendored Cordis | `@shanhai/kernel` K1 组合运行时 | 接口对齐，实现自写 |
| Fiber 六态（PENDING/LOADING/ACTIVE/FAILED/UNLOADING/DISPOSED） | 同 | 照搬 |
| epoch 驱动的依赖 reload/unload | 同 | 依赖实现 uid 串变化触发重载，照搬 |
| Context 是 Proxy（`ctx.xxx` 直接读服务） | 同 | 照搬（非 `ctx.get()`） |
| `ctx.isolate`（作用域隔离）/ `ctx.intercept`（配置拦截） | 同 | 照搬 |
| `inject` = 数组 \| map（含拦截配置） | 同 | 照搬 |
| Service 符号（invoke/check/extend/resolveConfig） | 同 | 照搬 |
| 事件五种 dispatch（emit/parallel/serial/bail/waterfall） | 同 | 照搬 |
| `@Inject()` 装饰器 | 同 | 照搬 |
| `ctx.plugin(plugin, config)` → Fiber | 同 | 照搬（三种形态 Function/Constructor/Object） |
| `@deepseek-ai/dsh-<name>` | `@shanhai/<name>` | 前缀换成本项目 |
| 双端包 `/client` | `kernel-modules` + `/client` 导出 | 命名对齐 |
| 能力缝（Definition/Provider/Consumer） | 同，一个能力一个包 | 照搬 |
| 不可变 Package + 版本指针 | K2 版本生命周期 | 照搬 |
| 自修改 `dsh-tool-cordis` | K5 自修改 | 照搬 |
| `__DSH_BOOT__` 模块系统 | K3 模块系统 | 照搬 |
| 传输抽象 `toFetchHandler` | IPC transport | 照搬思路 |
